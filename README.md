# Глобальный ИИ — веб-версия (правила v0.3)

Многопользовательская игра 2026–2040 для 1–16 игроков. Node 22, только stdlib, без `npm install`.
Правила: `docs/ПРАВИЛА_v0.3.md` (редакция v0.2 сохранена в `docs/ПРАВИЛА_v0.2.md`). Сервер — единственный источник истины, клиент только показывает и отправляет намерения.

Отличия v0.3: страна выдаётся игроку случайно (экран ознакомления и кнопка «Готов» вместо драфта) и воевать можно только со странами-игроками. Обе механики откатываются к v0.2 флагами конфига: `limits.draftMode: "pick"` и `war.allowNpcTargets: true`.

Развёртывание с нуля, зависимости и диагностика: `DEPLOY.md`.

## Запуск

```
node server.js            # http://localhost:3000
PORT=8080 node server.js  # другой порт
ADMIN_TOKEN=секрет node server.js
```

Если `ADMIN_TOKEN` не задан, он генерируется и печатается в консоль при старте.
Админка: `http://localhost:3000/admin`.

## Как играть вдвоём с одного ПК

1. Откройте два окна в режиме инкогнито (у каждого свой `localStorage`, поэтому свои токены игроков).
2. В первом: ник → «Создать комнату» → получите 5-буквенный код (например, `СЛОВО`).
3. Во втором: другой ник + этот код → «Войти».
4. В первом (хост) нажмите «Все здесь» — каждому игроку случайно выдаётся страна. Откроется брифинг в три колонки: слева дипломатический расклад на старте и кто за кого играет, в центре большая карта (ваша страна разгорается золотом, камера наезжает на неё и возвращается к миру), справа название, стартовые шкалы, опора и узкие места. Нажмите «Готов»; игра стартует, когда готовы все или истёк таймер ознакомления (2 мин). При `limits.draftMode: "pick"` вместо этого работает драфт v0.2 с выбором плиток и кнопкой 🎲.
5. Распределите очки в центре экрана, при необходимости торгуйтесь/предлагайте отношения, нажмите «Сдать ход». Атака доступна только по странам-игрокам (у NPC в колонке атаки стоит «—»), если не включён `war.allowNpcTargets`. Ход разрешается, когда сдали все, истёк таймер (10 мин) или хост нажал «Завершить ход».

Закрыли вкладку — токен остаётся в `localStorage`, при открытии страницы вход восстановится. Состояние комнат сохраняется в `data/rooms.json` и переживает перезапуск сервера.

## Проверки

```
python tools/extract.py        # пересоздать data/default_config.json из source/ (падает, если эффект не распознан)
                              # внимание: выгрузка из текущих книг даёт конфиг, отличный от закоммиченного
node tools/selfcheck.js        # формулы против Excel, переход года, регрессии
node tools/smoke.js            # сам поднимает сервер, два бота играют партию до 2040 (~30 с)
PORT=3111 ADMIN_TOKEN=test node server.js &
BASE=http://localhost:3111 node tools/e2e.js
```

Отдельный бот (играет как обычный клиент, через HTTP API):

```
node tools/bot.js --create                         # создаёт комнату, печатает код и ждёт хоста
node tools/bot.js --room КОД --nick Бот --base http://localhost:3000
```

## Админка и конфиг

В `/admin` вводится `ADMIN_TOKEN`, далее разделы: формулы (JS-выражения; контекст `res, sph, rel, pow, ln, min, max, ces(ids,rho), geo(weights)`), победа, таймеры, дипломатия (в т.ч. формулы шансов NPC), войны, лимиты, а также страны (старт), технологии, D60, статусы. «Проверить» — разбор JSON, структура, компиляция формул, selfcheck (расхождение с Excel США при изменённых формулах — это предупреждение, не ошибка). «Сохранить» пишет `data/config.json` (только если нет ошибок). Изменения применяются к **новым** комнатам; у существующих комнат конфиг зафиксирован.

Структурные эффекты (`techs[].effects`, `blackSwans[].effects`): `{target:"res:<id>"|"sph:<id>"|"all_spheres"|"mod:<key>", kind:"PZ"|"VZ"|"PP"|"VP"|"MOD", value, ttl?}`.

## HTTPS в локальной сети (телефоны, планшеты)

Ничего выпускать руками не нужно: при старте `server.js` сам проверяет `certs/` и, если надо,
выпускает самоподписанный сертификат через `openssl` (он есть в составе Git for Windows).
В консоли печатаются обе ссылки — http и https по всем IP машины:

```
node server.js
«Глобальный ИИ»: http://localhost:3000   админка: http://localhost:3000/admin
  https:    https://localhost:3443/
  с телефона: https://172.18.0.24:3443/   (самоподписанный — принять предупреждение)
```

Телефон должен быть в той же Wi-Fi-сети; открываем ссылку `https://<IP>:3443/` с телефона.
Если Windows Firewall спросит про доступ для Node — разрешить для частных сетей.

Когда сертификат перевыпускается сам:

| Ситуация | Что делает сервер |
|---|---|
| `certs/` нет | выпускает сертификат, пишет строку `[tls] сертификат выпущен` и SHA-256 |
| IP машины сменился (DHCP) и его нет в SAN | перевыпускает автоматически, пишет причину |
| сертификат на месте и IP совпадает | ничего не делает |
| `openssl` не найден | пишет одну строку и работает только по HTTP, без падения |

Переменные окружения:

| Переменная | Смысл |
|---|---|
| `HTTPS_PORT` | порт HTTPS, по умолчанию `3443` (HTTP остаётся на `PORT`) |
| `NO_HTTPS=1` | полностью отключить HTTPS: ни генерации, ни второго слушателя |
| `TLS_KEY`, `TLS_CERT` | свои ключ и сертификат; автогенерация их не трогает никогда |
| `EXTRA_SAN` | дописать записи в SAN, напр. `EXTRA_SAN="IP:10.0.0.5,DNS:myhost"` |
| `CERT_DAYS` | срок, по умолчанию 825 дней (больше браузеры не принимают) |
| `OPENSSL` | путь к openssl, если он не в PATH |

Перевыпустить принудительно: `node server.js --regen-cert` (выпускает и выходит, сервер не поднимает).

В SAN попадают: `DNS:localhost`, имя машины и `<имя>.local`, `IP:127.0.0.1` и все IPv4-адреса
всех активных адаптеров — поэтому переключение Wi-Fi/Ethernet/VPN сертификат не ломает.

### Про предупреждение браузера — честно

Сертификат **самоподписанный**. Публичный центр сертификации сертификат на приватный IP
(`172.18.x.x`) не выдаст в принципе, поэтому любой браузер при первом заходе покажет
«Подключение не защищено» / `NET::ERR_CERT_AUTHORITY_INVALID`. Варианты:

1. **Принять один раз** — «Дополнительно» → «Перейти на сайт». Быстро, но на каждом устройстве
   и после очистки данных браузера придётся повторить. Для игры на вечер этого достаточно.
2. **Импортировать `certs/server.crt` в доверенные корневые** — предупреждения больше не будет:
   - **Windows:** двойной клик по `certs/server.crt` → «Установить сертификат» → «Локальный компьютер»
     → «Поместить в хранилище» → «Доверенные корневые центры сертификации». Браузер перезапустить.
     (Firefox смотрит в своё хранилище: Настройки → Сертификаты → «Просмотр сертификатов» → «Импорт».)
   - **Android:** скинуть файл на телефон → Настройки → Безопасность → Шифрование и учётные данные
     → «Установить сертификат» → «Сертификат ЦС» (система предупредит, что сеть может отслеживаться —
     это нормально для своего сертификата). Chrome на Android 11+ пользовательские ЦС для сайтов
     учитывает не всегда, так что вариант 1 там зачастую проще.
   - **iOS/iPadOS:** открыть `.crt` в Safari → профиль скачается → Настройки → «Профиль загружен»
     → «Установить». Затем **обязательно** Настройки → Основные → Об этом устройстве →
     «Доверие сертификатам» → включить полное доверие, иначе Safari всё равно будет ругаться.

Приватный ключ `certs/server.key` лежит рядом и в репозиторий не попадает — `certs/` в `.gitignore`.
При смене IP (DHCP) сертификат перевыпускается на старте автоматически, но уже принятое
исключение/импортированный сертификат на устройствах после этого придётся принять заново.
